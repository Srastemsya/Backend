# Приёмка комнаты v2

Проверять HTTP API через Nginx по [контракту комнаты v2](../../contracts/lobby-v2.md). Использовать изолированный стенд, dev-участников `person1` … `person10`, одного постороннего и управляемое время. Наборы данных описаны в [BE-L01](implementation.md#be-l01--стендовые-данные). Ожидаемый порядок карточек выводится из контракта и опубликованных данных стенда, без чтения реализации.

Критерии первого релиза D03-05, D03-06, D03-07 и ограничение пула комнаты в 20 карточек заменяются критериями ниже по мере выполнения пакетов. Остальные критерии [приёмки Discovery v1](../discovery-v1/acceptance.md) действуют без изменений.

Каждый пакет проверяется на своей сборке. Критерии предыдущих пакетов комнаты v2 входят в регрессию следующего.

## BE-L01 · Стендовые данные

| ID | Действие | Ожидаемый результат |
|---|---|---|
| L01-01 | Войти под `person6` … `person10`. Повторить вход под `person1` на стенде с томами прежней сборки | Профили завершены, каталог и комнаты доступны. `userId` участников 1–5 не изменились. |
| L01-02 | Пройти все страницы `GET /feed/candidates?kind=EVENT&localDate=2090-02-01` | Ровно 35 карточек `dev-lobby-mix-01` … `35` по возрастанию номера. Категория каждой соответствует таблице BE-L01. |
| L01-03 | Запросить выдачу `kind=EVENT` с `categoryId=dev-lobby-short`, затем `dev-lobby-two` | 4 и 14 карточек по возрастанию номера. |
| L01-04 | Повторить запуск Compose. Запросить наборы `dev-swipe-places` и `dev-swipe-events`. Повторить INT-00 | Дублей нет, в прежних наборах по 22 карточки, сервисы готовы. |

## BE-L02 · Пул из 10 и номер раунда

| ID | Действие | Ожидаемый результат |
|---|---|---|
| L02-01 | Запустить комнату из четырёх на наборе `dev-swipe-events`, прочитать snapshot всеми участниками | В раунде ровно 10 первых карточек набора в порядке каталога. Пул и состав одинаковы у всех. `number=1`. |
| L02-02 | Всем пропустить все карточки и завершить раунд. Повторить ещё дважды | Раунд `number=2` из следующих 10 карточек без повторов, затем `number=3` из 2 карточек, затем `EXHAUSTED`, `round=null`. |
| L02-03 | Запросить `GET /feed/candidates` на наборе из 22 карточек | Первая страница содержит 20 карточек и курсор. |
| L02-04 | Повторить D03-03, D03-04, D03-08, D03-09, D03-10, INT-01, INT-02 | Критерии выполняются. |

## BE-L03 · Порог 70% и поля результата

| ID | Действие | Ожидаемый результат |
|---|---|---|
| L03-01 | В комнате из пяти дать карточке три лайка и завершить раунд. В следующем раунде дать карточке четыре лайка | После трёх лайков матча нет, открыт следующий раунд. После четырёх — `MATCHED` с этой карточкой. |
| L03-02 | Проверить границы для двух, трёх и десяти участников | Двое: один лайк не даёт матч, два дают. Трое: два лайка не дают матч, три дают. Десять: шесть не дают, семь дают. |
| L03-03 | Дать двум карточкам лайки выше порога, сначала поровну, затем с разницей. Последние два участника завершают проход параллельно | При равенстве побеждает более ранняя в пуле, при разнице — карточка с большим числом лайков. Все видят один `MATCHED`. |
| L03-04 | Прочитать результат после матча и snapshot до матча | `result = {winner, basis: "THRESHOLD", likes, memberCount}`, значения соответствуют голосам и составу. До матча `result=null`. |
| L03-05 | Повторить L02-01 … L02-04 | Критерии выполняются. |

## BE-L04 · Срок на каждый раунд

| ID | Действие | Ожидаемый результат |
|---|---|---|
| L04-01 | Запустить комнату в управляемый момент T | У первого раунда `expiresAt = T + 30 минут`. |
| L04-02 | Завершить первый раунд без матча в момент T + 20 минут. Прочитать комнату в T + 30 минут | У второго раунда `expiresAt = T + 50 минут`. В T + 30 минут комната в `VOTING` со вторым раундом. |
| L04-03 | Прочитать комнату в T + 50 минут. Попытаться проголосовать и завершить проход | `CLOSED`, `round=null`, `result=null`. Голос и завершение состояние не меняют. |
| L04-04 | Перезапустить swipes посреди второго раунда. Повторить L03-01 … L03-05 | Сохранены состав, `number`, `expiresAt`, пул, свои голоса, признаки завершения и `version`. Критерии выполняются. |

## BE-L05 · Следующий пул по весам категорий

Комната из пяти на смешанном наборе, фильтры `kind=EVENT`, `localDate=2090-02-01`.

| ID | Действие | Ожидаемый результат |
|---|---|---|
| L05-01 | Запустить комнату | Первый пул — карточки 01–10 в порядке каталога. |
| L05-02 | В первом раунде дать каждой карточке `dev-lobby-a` по три лайка, карточки `dev-lobby-b` пропустить всем. Прочитать второй раунд | Во втором пуле сначала карточки `a`, затем категории без показов `c`, карточек `b` нет, пока есть другие. Внутри категории порядок каталога. Показанных ранее карточек нет. |
| L05-03 | Во втором раунде проголосовать так, чтобы сумма весов за два раунда и веса одного второго раунда давали разный порядок категорий. Прочитать третий раунд | Порядок третьего пула соответствует сумме голосов двух раундов. |
| L05-04 | Запустить комнату с фильтром одной категории и довести до второго раунда | Оба пула идут в порядке каталога без повторов. |
| L05-05 | Последние два участника завершают раунд без матча параллельно. Перезапустить swipes, прочитать комнату всеми участниками | Создан ровно один следующий раунд. Пул и порядок одинаковы у всех до и после перезапуска. |
| L05-06 | Между раундами опубликовать подходящее событие другим аккаунтом. Повторить L04-01 … L04-04 | Событие входит в следующий пул и занимает место по весу своей категории и порядку каталога. Критерии выполняются. |

## BE-L06 · Итог по баллам при исчерпании

| ID | Действие | Ожидаемый результат |
|---|---|---|
| L06-01 | На наборе `dev-lobby-two` пройти оба раунда без порога, оставив единственного лидера в первом раунде | `MATCHED`, `round=null`, `result.basis="TOP_SCORE"`, победитель — карточка с максимумом лайков за все раунды. `likes` и `memberCount` соответствуют голосам и составу. |
| L06-02 | Дать равный максимум карточкам разных раундов, затем в новой комнате двум карточкам одного раунда | Побеждает карточка более раннего раунда. Внутри раунда — более ранняя в пуле. |
| L06-03 | На наборе `dev-lobby-short` пропустить все карточки всеми участниками | `EXHAUSTED`, `round=null`, `result=null`. |
| L06-04 | Получить матч по порогу в первом раунде. Запустить комнату с фильтрами без кандидатов | Матч: `result.basis="THRESHOLD"`. Пустой старт: `EXHAUSTED`, `round=null`, `result=null`. |
| L06-05 | Последние два участника завершают последний раунд параллельно. Повторить завершение, проголосовать в старый раунд, держать long poll организатора | Все видят один результат. Повтор возвращает текущий snapshot, голос даёт `409 STALE_ROUND`. Long poll доставляет итоговую версию. Чужих голосов в ответах нет. |
| L06-06 | Повторить L05-01 … L05-06 | Критерии выполняются. |

## BE-L07 · Сверка документов и сквозной прогон

| ID | Действие | Ожидаемый результат |
|---|---|---|
| L07-01 | Прочитать мобильный контракт, Discovery v1, спецификацию бэкенда, документацию swipes и README бэкенда. Пройти по ссылкам | Правила комнат совпадают с контрактом комнаты v2. Прежних правил комнаты нет. Ссылки открываются. |
| L07-02 | Выполнить сквозной сценарий релиза на чистом Compose | Регистрация, публикация, видимость события в новых пулах, запись на последнее место, вход по ссылке и итог комнаты через long polling проходят на одной идентифицированной сборке. |
| L07-03 | Повторить на той же сборке критерии L02 … L06 и INT-00, INT-01, INT-02 | Критерии выполняются. |

В отчёте указать версию стенда, тестовые данные, выполненные сценарии, фактические статусы и ссылки на неизменённые отчёты прогонов по [правилам тестирования](../../../workflow/rules/testing.md).
