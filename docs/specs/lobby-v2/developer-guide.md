# Памятка разработчика комнаты v2

Только для роли Developer. PM и Tester этот файл не читают: он описывает устройство кода.

Читать вместе с разделом своего пакета в [implementation.md](implementation.md). Имена функций указаны по состоянию на базу `dev`. Номера строк не указаны намеренно: ищите по имени.

## Карта кода

| Файл | Что в нём |
|---|---|
| `backend/runtime/swipes.py` | Вся логика одиночной выдачи и комнат |
| `backend/runtime/swipes_schema.py` | Таблицы swipes. Менять не требуется |
| `backend/runtime/catalog_schema.py` | Dev-данные каталога, функция `seed_swipes` |
| `backend/runtime/identity.py` | Dev-участники, список `CONTACTS` |
| `backend/README.md` | Описание запуска и dev-данных |

Состояние комнаты хранится одним JSON в колонке `swipe_rooms.snapshot`. Миграции таблиц для новых полей не нужны: добавляйте ключи в этот JSON. Читайте новые ключи через `.get(...)` со значением по умолчанию, потому что на стендах остаются комнаты, созданные до изменения.

Функции комнаты в `swipes.py`:

| Функция | Роль |
|---|---|
| `open_round(data, items)` | Создаёт раунд из кандидатов или ставит `EXHAUSTED` |
| `start(...)` | Запуск комнаты, вызывает `open_round` |
| `winner(current, member_count)` | Выбирает победителя раунда |
| `finish(...)` | Завершение прохода. После последнего участника подводит итог |
| `snapshot(room, user_id)` | Собирает публичный DTO. Отдаёт только перечисленные в нём поля |
| `save(db, room, changes)` | Пишет snapshot и `expires_at`, повышает версию |
| `close_expired(...)` | Переводит просроченную комнату в `CLOSED` |
| `request_clock(request)` | Часы запроса, в dev управляются заголовком `X-Dev-Swipes-Now` |

Новое поле раунда появляется в ответе API только после того, как вы добавили его в `snapshot()`. Внутренние ключи (`used`, `completions`, новые `history` и `roundNumber`) в ответ попадать не должны.

## Модуль правил и модульные тесты

Создаётся в BE-L03, дополняется в BE-L05 и BE-L06.

- `backend/runtime/room_rules.py` — только чистые функции. Никаких импортов FastAPI, базы, Redis и модуля `runtime`. На вход обычные списки и словари, на выход значения.
- `backend/services/swipes/tests/test_room_rules.py` — тесты на `unittest`. В начале файла добавить каталог `backend/runtime` в `sys.path`.
- `backend/services/swipes/tests/run.sh` — по образцу `backend/tests/run.sh`: запускает `python3 -m unittest -v test_room_rules`, пишет отчёт в `reports/<метка времени>.md` с командой, кодом выхода и числом пройденных, упавших и пропущенных. Отчёты руками не править.

Тесты запускаются без Docker: `sh backend/services/swipes/tests/run.sh`.

## BE-L01

1. `identity.py`: расширить `CONTACTS` до `person1` … `person10`. Больше ничего не менять: ID считается функцией `dev_account_id(index)`, вставка уже идемпотентна.
2. `catalog_schema.py`: добавить функцию `seed_lobby(db)` по образцу `seed_swipes` и вызвать её из `seed` рядом с `seed_swipes`. Все вставки с `ON CONFLICT DO NOTHING`.
3. Категории: `kinds = ["EVENT"]`, позиции 92–96, чтобы не пересечься с существующими.
4. События: `published = true`, организатор `dev_account_id(1)`, конец через 2 часа после начала, зона `Asia/Vladivostok`, цена 1000.
5. Категория смешанного набора по номеру N:
   - N от 1 до 10: нечётный → `dev-lobby-a`, чётный → `dev-lobby-b`.
   - N от 11 до 35: `(N − 11) % 3` равно 0 → `a`, 1 → `b`, 2 → `c`.

Проверка: `GET /v1/feed/candidates?kind=EVENT&localDate=2090-02-01` отдаёт 20 карточек и курсор, следующая страница — ещё 15.

## BE-L02

1. Рядом с `PAGE_SIZE` добавить константу `ROOM_POOL_SIZE = 10`. В `open_round` заменить срез `[:PAGE_SIZE]` на `[:ROOM_POOL_SIZE]`. `PAGE_SIZE` и функцию `feed_page` не трогать.

## BE-L03

1. В `room_rules.py` написать `passes_threshold(likes, member_count)`: вернуть `likes * 10 >= member_count * 7`. Дробные числа и `0.7` не использовать: `0.7 * 3` в Python меньше 2.1 и даёт неверную границу.
2. Тесты `passes_threshold`, пары (лайки, участники):

   | Ложь | Истина |
   |---|---|
   | (1, 2), (2, 3), (2, 4), (3, 5), (4, 6), (4, 7), (6, 10) | (2, 2), (3, 3), (3, 4), (4, 5), (5, 6), (5, 7), (7, 10) |

3. В `winner` заменить условие `counts[index] * 2 > member_count` на вызов `passes_threshold`. Вернуть пару: ссылку на карточку и число её лайков, либо `None`. Выбор `counts.index(max(counts))` оставить: он уже даёт более раннюю карточку при равенстве.
4. В `finish` при матче записать `result = {"winner": ..., "basis": "THRESHOLD", "likes": ..., "memberCount": member_count}`.

## BE-L04

1. В `swipes.py` уже есть преобразование времени в строку в функции `invite` (`...isoformat().replace("+00:00", "Z")`). Вынести его в маленькую функцию и использовать в обоих местах.
2. `open_round` получает третий аргумент `now` и пишет в раунд `expiresAt` — строку для `now + LIFETIME`.
3. Обе точки вызова `open_round` передают время запроса: в `start` это `clock()`, в `finish` получите `now = request_clock(request)()` один раз в начале обработчика.
4. Колонка `expires_at` должна всегда равняться сроку текущего раунда. Надёжнее всего выставлять её в `save()`: если в snapshot есть раунд с `expiresAt`, записать `room["expires_at"] = datetime.fromisoformat(...)`. После этого строку `room["expires_at"] = clock() + LIFETIME` в `start` удалить.
5. В `snapshot()` добавить `expiresAt` в словарь раунда через `.get`.
6. `close_expired` и `get_snapshot` менять не нужно: они читают `room["expires_at"]`.

Проверка часами стенда: старт с `X-Dev-Swipes-Now: 2089-01-01T00:00:00Z`, завершение первого раунда без матча с `…T00:20:00Z`. У второго раунда `expiresAt` равен `2089-01-01T00:50:00Z`. Чтение с `…T00:30:00Z` даёт `VOTING`, с `…T00:50:00Z` — `CLOSED`.

## BE-L05

1. В `finish`, когда завершил последний участник и до вызова `winner`, добавить запись в `data.setdefault("history", [])`:

   ```json
   {"number": 1, "cards": [{"ref": {"kind": "EVENT", "id": "…"}, "categoryId": "…", "likes": 3, "passes": 2}]}
   ```

   Карточки в порядке пула. К этому моменту каждый участник проголосовал по каждой карточке, поэтому `passes = member_count − likes`.
2. `room_rules.py`: `category_weights(history)` возвращает словарь «категория → сумма (likes − passes)».
3. `room_rules.py`: `order_candidates(items, weights)` возвращает `sorted(items, key=...)` с ключом «минус вес категории», вес по умолчанию 0. Сортировка Python устойчива и сама сохраняет порядок каталога при равных весах. Вторичный ключ по ID не добавлять.
4. В `open_round`: сначала отфильтровать показанные (`data["used"]`), затем `order_candidates`, затем срез до 10. Другой порядок шагов даёт неверный пул.
5. Запись в `history` обязана попасть в snapshot раньше вызова `open_round`, иначе последний раунд не повлияет на веса.

Пример для модульного теста на смешанном наборе BE-L01, пять участников.

| Раунд | Голоса | Веса после раунда |
|---|---|---|
| 1, карточки 01–10 | Каждая карточка `a` получает 3 лайка и 2 пропуска. Карточки `b` пропускают все | a = +5, b = −25, c = 0 |
| 2 | Каждая карточка `a` получает 2 лайка и 3 пропуска. Карточку 13 пропускают все | a = −4, b = −25, c = −5 |

- Пул 2: `11, 14, 17, 20, 23, 26, 29, 32, 35, 13` (девять `a`, затем первая `c`).
- Пул 3: `16, 19, 22, 25, 28, 31, 34, 12, 15, 18` (семь `c`, затем три `b`).

Пул 3 проверяет, что веса суммируются за все раунды: если считать только последний раунд, первыми встали бы карточки `b`.

## BE-L06

1. `room_rules.py`: `top_score(history)` обходит раунды по порядку и карточки по порядку. Запоминает карточку, только если её лайков строго больше текущего максимума. Так при равенстве остаётся более ранняя. Возвращает пару (ссылка, лайки) или `None`, если максимум равен 0 или история пуста.
2. В `open_round`, в ветке «кандидатов нет»: вызвать `top_score(data.get("history", []))`.
   - Есть лидер: `state="MATCHED"`, `round=None`, `result = {"winner", "basis": "TOP_SCORE", "likes", "memberCount": len(data["members"])}`.
   - Нет лидера: как сейчас, `state="EXHAUSTED"`, `round=None`.
3. При старте история пуста, поэтому пустой пул по-прежнему даёт `EXHAUSTED` без отдельной проверки.
4. Тесты `top_score`: пустая история → `None`; все лайки 0 → `None`; один максимум во втором раунде → он; равный максимум в раундах 1 и 2 → карточка раунда 1; равный максимум у двух карточек одного раунда → более ранняя.

Проверка на наборе `dev-lobby-two`, три участника: в первом раунде карточка 03 получает 2 лайка, во втором карточка 12 получает 2 лайка, остальные меньше. Итог: `MATCHED`, победитель `dev-lobby-two-03`, `basis=TOP_SCORE`, `likes=2`, `memberCount=3`, `round=null`.

## Проверки перед отчётом

1. Модульные тесты, начиная с BE-L03: `sh backend/services/swipes/tests/run.sh`.
2. Чистый стенд из каталога `backend`, имя проекта и порт свои для пакета:

   ```sh
   NGINX_PORT=18090 docker compose -p srastemsya_l0x -f compose.yaml -f compose.dev.yaml up --build -d --wait
   curl -i http://127.0.0.1:18090/swipes/health
   ```

3. Вручную пройти через Nginx пример проверки из раздела своего пакета.
4. Повторить команду запуска и убедиться, что стенд поднимается без ошибок и дублей.
5. Остановить стенд командой `down` без удаления томов чужих проектов.

В `dev_report.md` указать коммит, команды и результаты. В `test_packet.md` — только публичное: команду запуска, адрес, участников, наборы данных и заголовок часов. Имена функций, структуру snapshot и содержание этой памятки в `test_packet.md` не переносить.
