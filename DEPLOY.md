# Переменные деплоя API

В GitHub откройте **Settings → Environments** и создайте два окружения.

| Environment | Ветка | Стенд | Внутренний порт |
| --- | --- | --- | --- |
| `staging` | `dev` | Тестовый API | `18080` |
| `demo` | `main` | API для защиты | `8080` |

Оба стенда подключаются по SSH к `tech@176.53.253.166:22`. Адрес, пользователь и порт заданы в [workflow](.github/workflows/backend.yml).

## GitHub Environment secrets

Добавьте в каждое окружение через **Environment secrets**.

| Имя | Значение |
| --- | --- |
| `API_DOMAIN` | Отдельное DNS-имя стенда в нижнем регистре, например `api-demo.example.com`. Без схемы, пути или порта |
| `SSH_PRIVATE_KEY` | Полное содержимое отдельного приватного ключа автоматизации для GitHub Actions. Его публичную часть добавьте в `authorized_keys` пользователя деплоя |
| `SSH_KNOWN_HOSTS` | Проверенная запись публичного ключа SSH-сервера в формате `known_hosts`. Для порта отличного от 22 имя хоста в записи имеет вид `[HOST]:PORT` |

Для двух стендов на одном сервере SSH-настройки могут совпадать. Значения `API_DOMAIN` должны различаться. Оба домена направьте на сервер, порты 80 и 443 нужны для выпуска сертификатов и HTTPS.

## Переменные на сервере

Создайте под пользователем деплоя два файла с правами `0600`.

- `~/srastemsya/staging/.env`
- `~/srastemsya/demo/.env`

В каждом задайте собственные случайные URL-safe пароли.

| Имя | Значение |
| --- | --- |
| `IDENTITY_DB_PASSWORD` | Пароль базы Identity |
| `CATALOG_DB_PASSWORD` | Пароль базы Catalog |
| `SWIPES_DB_PASSWORD` | Пароль базы Swipes |
| `DEV_OTP` | Необязательный код mock OTP. По умолчанию `0427` |

Первичная настройка Docker, Nginx, Certbot и прав пользователя описана в [инструкции бэкенда](backend/README.md#github-actions-и-стенды-мероприятия). После настройки push в `dev` обновит тестовый стенд, а merge или push в `main` обновит стенд для защиты.
