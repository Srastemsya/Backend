Проверки выполняются через Nginx на изолированном стенде с dev-участниками `person1`…`person10`, одним посторонним и управляемым временем (шапка docs/specs/lobby-v2/acceptance.md). Ожидаемый порядок карточек выводится из контракта (для EVENT — `startsAt, id`) и опубликованных данных стенда, без чтения реализации. Каждый пакет проверяется на своей сборке; критерии BE-L01 входят в регрессию.

В этом пакете действуют только два правила комнаты v2: пул раунда ≤ 10 карточек и поле `Round.number` с нумерацией с 1 (docs/contracts/lobby-v2.md#dto, #пул-раунда). Порог матча остаётся Discovery v1 (строгое большинство), порядок следующего пула — порядок каталога, срок комнаты — 30 минут от старта первого раунда, итог при исчерпании — `EXHAUSTED`.

## Обязательные критерии

- **AC-01 (L02-01).** Комната из четырёх участников на наборе `dev-swipe-events` (22 карточки). После старта snapshot, прочитанный всеми участниками, содержит раунд ровно из 10 первых карточек набора в порядке каталога; пул и зафиксированный состав одинаковы у всех; `round.number = 1`.
- **AC-02 (L02-02).** В той же комнате все участники пропускают все карточки каждого раунда и завершают проход; повторить ещё дважды. Результат: раунд `number = 2` из следующих 10 карточек без повторов с первым раундом, затем раунд `number = 3` из оставшихся 2 карточек, затем `EXHAUSTED`, `round = null`. Номера раундов монотонны (1 → 2 → 3), пулы не пересекаются, суммарно показаны все 22 карточки.
- **AC-03 (L02-03).** Одиночная выдача не изменилась: `GET /feed/candidates` на наборе из 22 карточек возвращает первую страницу из 20 карточек и не-пустой `nextCursor`; следующая страница — оставшиеся 2 карточки и `nextCursor = null`.
- **AC-04 (L02-04).** Регрессия Discovery v1 выполняется на этой же сборке: D03-03, D03-04, D03-08, D03-09, D03-10 (docs/specs/discovery-v1/acceptance.md#21…28), INT-01, INT-02 (там же #30…31). Все перечисленные критерии — PASS.
- **AC-05 (Документация, implementation.md BE-L02 шаг 3, правило 6).** В одном комплекте с кодом обновлены:
  1. `Round` в docs/contracts/mobile-api.md#be-04--подборка-и-комната — содержит `number` (порядковый номер раунда в комнате, начиная с 1), существующие поля сохранены;
  2. docs/contracts/discovery-v1.md#свайпы-в-комнате — правило «Максимум 20 карточек в раунде» приведено в соответствие с контрактом комнаты v2 (пул ≤ 10);
  3. описание комнат в README бэкенда (backend/README.md) отражает пул из 10 карточек и нумерацию раундов.
  Ссылки в изменённых документах открываются; docs/contracts/lobby-v2.md остаётся источником приоритета и не противоречит обновлённым документам.
- **AC-06 (Границы пакета, implementation.md «Не трогать» и «Правила для всех пакетов»).** Поведение вне пакета не изменилось: маршруты, статусы ошибок, приглашения, long polling, идемпотентность сохранены; правило матча (строгое большинство), порядок карточек в пуле (порядок каталога), срок комнаты (30 минут от старта первого раунда) и итог при исчерпании (`EXHAUSTED` без лидера по баллам) остались прежними; правила BE-L03…BE-L06 не реализованы заранее; каталог и identity не менялись. Гарантии BE-D03 сохранены: один итог при параллельных завершениях, монотонная `version`, уведомление long polling после фиксации в PostgreSQL, состояние комнаты переживает перезапуск процесса.
